# 益护夕阳 · App 体验版 V0.3

面向法学院队长评审的可交互原型。原始项目书与 `APP/app.txt` 保持不变。

V0.3 优先安卓安装包，保留网页版。已按用户确认移除自动朗读与音色设置；后续真人录音需求写入交接文档，拿到审核通过的音频后才显示播放器。

- 安卓安装包：https://mack-blip-space.github.io/yihu-xiyang-demo/downloads/yihu-xiyang-v0.3.apk
- 网页版：https://mack-blip-space.github.io/yihu-xiyang-demo/?v=03
- 交接材料：`交接材料/法学院内容与素材交接说明.html`，同目录有可编辑源文档、提交模板和任务登记表。
- 安卓工程、构建及更新方式：`安卓开发与交付说明.md`。

安卓包已完成编译和 Lint 检查，尚需队长在实际手机上验收安装、拨号界面、文件选择及系统分享。网页版自动化测试不替代真机验收。

## 打开方式

**给队长演示：双击 `益护夕阳-双击体验.html`。** 全部脚本与样式已内嵌，无外部依赖。也可发送 `益护夕阳-初版演示包.zip`，解压后打开同名 HTML。

直接用 Chrome / Edge 打开 `dist/index.html`，无需安装依赖或构建。

更推荐在本目录运行：

```powershell
python -m http.server 4173 --bind 0.0.0.0 --directory dist
```

电脑访问 `http://localhost:4173`。手机与电脑连接同一 Wi-Fi 后，访问 `http://电脑局域网IP:4173`，需系统允许该端口访问。关闭命令窗口停止服务。

浏览器按来源隔离本机存储。文件方式、localhost、局域网地址以及线上网址之间不共享记录。

## 两分钟演示

1. 首页点击“我要维权”，点击“填入演示情景”。
2. 下一步查看虚构经过，再下一步选择示例图片或 PDF（可跳过）。
3. 核对并勾选演示说明，确认保存。
4. 查看记录和流程状态，刷新后仍可查看；查看附件、导出文本。
5. 打开“学法与问法”，体验搜索、分类和详情；在“我的”体验大字版、紧急联系人和家人协助。

## 真实边界

- 无后端、无登录、无 AI 调用、无自动数据上报、无机构接入或正式案件编号。主动点击导出后可选择保存或分享目标。
- 机构接收和后续处理明确为未发生/待接入，不能自动推进假进度。
- 附件确认提交后持久保存，提交前刷新需重新选择；草稿文字保存在 localStorage。
- 附件限制：JPG、PNG、WebP、PDF，最多五份，每份 5 MB。存储失败不清除草稿。
- 导出为文本记录和附件清单，不包含附件本体；附件可以逐个保存。
- “联系家人”需先保存联系人，点击拨号按钮才调用系统电话处理程序。
- 演示数据未加密，仅适合虚构信息；清除浏览器网站数据将删除本机记录。
- 匿名分享不跨设备同步，也不会对其他访客公开；示例不是实际用户发帖。电话号码、证件号、连续长数字及邮箱有基础输入提醒，但不构成完整内容审核。
- 本版没有朗读功能，没有购买配音服务，也没有获取或克隆任何人的声音。可选播放器只展示通过审核的固定音频。
- 网页与安装版数据各自保存，暂不迁移或同步。体验包使用 Debug 签名，不是应用商店正式发行版。
- 正式推文、法律问答和法令留待法学院同学提供与审核，当前示例不是法律意见。

## 文件说明

| 文件 | 用途 |
|---|---|
| dist/index.html | 页面入口 |
| dist/styles.css | 响应式布局、色彩、适老字号 |
| dist/content.js | 法学院内容编辑入口，独立于交互逻辑 |
| dist/app.js | 路由、表单、存储与交互 |
| dist/features.js | 热线和本机匿名分享 |
| dist/mobile.js | 安卓返回键与文件导出、可选图片和审核音频 |
| capacitor.config.json | 应用名称、包名和内置网页目录 |
| scripts/prepare_android.py | 可重复生成的安卓配置、版本、图标 |
| 内容交接清单.md | 内容模板、审核要求、第一轮评审问题 |
| tests/smoke.py | 浏览器主要流程验证 |
| tests/features.py | 热线、匿名分享、大字布局及移除朗读验证 |
| tests/mobile.py | 原生接口模拟、音频边界、交接文档和 APK 完整性检查 |
| build-demo.py | 更新单文件体验版和分享 ZIP |

修改源码或内容后运行 `python build-demo.py`，再发送新生成的单文件或 ZIP。不要直接维护生成的单文件版本。
